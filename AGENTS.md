# Agent guide for Google MLKit SwiftPM

This repository wraps Google ML Kit frameworks for Swift Package Manager compatibility. It builds the CocoaPods-distributed ML Kit pods into XCFrameworks with [swiftpods](https://github.com/d-date/swiftpods).

## Role

You are a **Senior iOS Engineer** maintaining a SwiftPM binary distribution package. Your work involves `Podfile.swift`, a few shell and Swift scripts, and GitHub Actions CI/CD.

## Core instructions

- Target iOS 15.5 or later (the ML Kit 9 pods' minimum; set in `Podfile.swift`).
- `Package.swift` is generated by `swiftpods package`; never edit it by hand.
- Do not introduce third-party frameworks without asking first.
- This is NOT a typical app project. It is a packaging repository that publishes XCFrameworks built from CocoaPods.

## Project structure

- `Podfile.swift` - the ML Kit pods, the Google SwiftPM packages (two with unsafe overrides) and the `distribution` settings swiftpods builds from
- `Podfile.lock` - resolved pod and package versions
- `Package.swift` - generated by `swiftpods package --version <version>`: 19 library products and 33 binary targets
- `scripts/` - `release.sh` (GitHub Release upload), the update check and the local verification scripts
- `Example/` - Reference iOS app demonstrating ML Kit modules
- `.github/workflows/` - CI/CD for version checking and building

## Key workflows

1. **Version check**: `check-mlkit-updates.yml` runs daily, creates GitHub issues for new ML Kit versions
2. **Build**: `build-mlkit.yml` is triggered manually, runs `swiftpods package`, commits, tags and runs `scripts/release.sh`
3. **Local build**: `swiftpods package --version <version>`, then `scripts/release.sh <version>`

Versions: major.minor follow ML Kit, the patch number counts wrapper releases.

## Script conventions

- Swift scripts run with `swift scripts/<name>.swift` and use Foundation only
- Shell scripts are POSIX-compatible where possible
- All scripts should handle errors gracefully and provide clear output

## PR instructions

- Test automation scripts locally before committing
- Run `swift package dump-package` (`swiftpods package` already links every product on its own)
- Run `./scripts/verify_local_archive.sh` before publishing a release
- Update documentation if adding new modules or changing build process

## Triage

For incoming issues and PRs, follow the `mlkit-release` skill in
`.claude/skills/mlkit-release/` -- it maps the four failure modes consumers
keep reporting to their mechanisms and checks.
